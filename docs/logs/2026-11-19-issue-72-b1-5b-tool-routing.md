## 2. 新增知识点 / 重点学习对象

### 2.1 评测方法学（Python / 通用）

- **“判分器”本身是最大风险点**：`task_success` 由多个子判定组合（工具/槽位/schema/接地/可接受集合/结果约束），其中一个子判定被写死（`acceptable_movie_ids = []`）就会让整张报表**静默虚高 9.3pp**，而所有其它指标看起来“正常”。学习价值：评测脚本要像生产代码一样做**输入完整性断言**（“golden 里该有集合却没有 → 直接报错”），并对“恒为 `None`/恒通过”的字段做哨兵检查。对应位置：报告 §1.1、§13 R-7；`scripts/eval/tool_eval.py` 的 `build_cases()` / `score_case()`。
- **in-sample vs held-out**：在同一批 fixture 上调规则得到的分数只能描述“这套形态在这批样本上如何”，不能外推为真实用户成功率。学习价值：任何“百分比”都要同时标注**样本来源、是否调优过、是否 held-out**。对应位置：`ai-user-workflows.md` §1.6 caveat；umbrella §7。
- **替身执行器（stand-in）的口径边界**：为了让 15 条 similar / 10 条 recommend 能被计分，评测脚本内置了确定性替身；于是 7/15、9/10 只证明“替身能命中可接受集合”，不证明生产信号（同导演）已实现。学习价值：**“能计分”≠“已实现”**，替身必须在报告里显式披露，且不得反向推导生产可用性。
- **判分自洽循环**：用同一套正则既抽取“查询文本里提到的约束”又校验“约束是否满足”，会得到自洽但未独立复核的结果（本例仅 8 例计分）。学习价值：识别“同一来源既当输入又当裁判”的评测设计缺陷。

### 2.2 SQL / MySQL 语义

- **多值 `genres[]` 的 AND 语义**：`HAVING COUNT(DISTINCT g.name) = len(genres)` 表达“同时含全部类型”，而 `g.name IN (...)` 是 OR；两者对同一句“1990 年代喜剧动作片”给出完全不同的结果集。学习价值：**“多值过滤”在契约层必须先定义 AND/OR**，否则执行器与 golden 会各写一套。对应位置：报告 §13 R-1、§7 Q11/Q19。
- **枚举的 DB 派生与语义变体**：`SELECT DISTINCT name FROM genres` 得到 56 个名称，但 `Sci-Fi`(457) 与 `Science Fiction`(2) 是同一语义的两个字符串；不做规范化就会出现“结果天差地别”。学习价值：**枚举不是写完就完，规范化/别名映射是数据契约的一部分**。

### 2.3 Ollama / 本地 LLM 工具调用

- **`tools` 字段 vs prompt 注入**：工具契约通过 Ollama `/api/chat` 的 `tools` 字段传入，prompt 里**不重写 schema**（避免双真值与 token 浪费）；`prompt_eval_count` 可用来实测“schema 到底吃了多少 token”（本例 1,265–1,284 > ≤900 估算）。对应位置：`ai-user-workflows.md` §1.4 / §1.6。
- **`temperature=0` 下的“确定性失败”**：G1 的 13 条失败全部可归因到具体机制（`model_calls = 0`），说明失败不是随机抖动；而 G0 的失败集中在“没走完该走的工具序列”（`incomplete_tool_sequence`），说明**小模型的瓶颈是步骤规划，不是参数格式**。学习价值：区分“结构化能力不足”与“格式不合规”——G2 只做 schema 校验（50.7%）几乎没有改善就是证据。

### 2.4 文档与状态治理

- **一处数字变更要横跨 6 份文档**：同一事实（G1 成绩）被架构 spec、子计划、issue 记录、umbrella、roadmap、评测契约 README 同时引用；漏改任何一处都会让后续 agent 读到两套真值。学习价值：**状态回填要按“引用链”遍历**，且历史记录用“旧值作废 + 指向新值”的方式保留（而非删掉历史），避免毁证。
- **”issue body 冻结“原则**：已发布到 GitHub 的正文由远端为准，本地 `## GitHub issue body` 不再改动，只更新 `## Internal tracking`；同时**不声称**远端 issue 已关闭。学习价值：本地规范记录与远端发布内容的边界要写清，否则本地编辑会造成“本地与远端不一致”的假象。
